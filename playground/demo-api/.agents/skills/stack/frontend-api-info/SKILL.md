# API 接口详情查询

## 核心功能

通过接口 ID 查询 API 的完整信息，并按标准模板格式化输出。

## 工作流程

### 1. 获取接口 ID

识别用户提供的接口标识：

- 直接数字 ID："12345"
- 接口名称 + ID："getUserInfo 接口，ID 是 12345"
- 从 URL 提取："/api/detail/12345"

如未提供 ID，询问：

> "请提供要查询的接口 ID（接口编号）"

### 2. 调用查询工具

使用 `get_api_details` 工具查询：

```
工具：get_api_details
参数：interfaceId = "接口ID"
```

### 3. 格式化输出

严格按照 `references/api-template.md` 模板格式化接口信息。

**接口路径处理规则**：

从接口详情返回的完整路径中提取有效的接口路径：

- 如果路径包含 `intl` 关键词：截取 `intl` 之后的部分（不包含 `/intl`）
- 如果路径包含 `cust` 关键词：截取 `cust` 之后的部分（不包含 `/cust`）
- 如果两个关键词都不存在：使用完整路径

**示例**：

- 原路径：`/api/v1/intl/user/info` → 输出：`/user/info`
- 原路径：`/system/cust/order/list` → 输出：`/order/list`
- 原路径：`/api/user/list` → 输出：`/api/user/list`

**输出规则**：

- 用户明确指定输出要求时：按用户要求执行
- 当涉及开发任务时，直接根据获取接口信息进行代码实施，无需输出
- 否则按默认文件结构输出

**默认文件结构**：

```
./developer/apiInfo/
└── {接口集合名称}-api.md        # 接口信息文档
```

## 示例

**用户**：查询接口详情 id 为 591421、591430

**执行流程**：

1. 识别接口 ID：591421、591430
2. 分别调用 `get_api_details` 工具
3. 读取 `references/api-template.md` 模板
4. 格式化并输出结果

## 错误处理

| 错误信息         | 原因                   | 解决方案                     |
| ---------------- | ---------------------- | ---------------------------- |
| token不能为空    | 未提供认证 token       | 提示用户在接口平台获取 token |
| 获取接口信息失败 | 接口 ID 不存在或无权限 | 确认 ID 是否正确，检查权限   |
| 请求失败         | 网络或服务异常         | 稍后重试或检查服务状态       |

## 依赖

- **接口详情 MCP 工具**：用于获取接口详情

  如找不到该工具，提示："建议安装 接口详情 MCP 工具"

## 常见问题

**Q: 如何获取接口 ID？**

A: 在接口管理平台的接口详情页 URL 中找到，或询问接口负责人。

**Q: 查询需要什么权限？**

A: 需要有效的平台 token，可在接口平台个人设置中获取。

**Q: 可以批量查询多个接口吗？**

A: 支持批量查询，逐个调用工具即可。
## V3 接口来源边界

- 接口来源变化后重新扫描契约，并记录变化、影响范围和未确认项；不能继续沿用过期接口信息。
