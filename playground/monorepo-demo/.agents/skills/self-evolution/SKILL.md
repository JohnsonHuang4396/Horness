# Self-Evolution Skill — Harness 自进化 SOP

本 Skill 负责对已完成的任务进行复盘分析，从执行过程数据和评审报告中提炼根因，输出可落地的 harness 工程加固方案，推动 Agent 系统持续改进。

---

## 核心原则

1. **数据驱动**：所有结论必须有具体问题来源（文件路径 + 行号 + 问题描述），禁止凭空推断
2. **根因导向**：不止于描述现象，必须追溯至 harness 规则/模板/流程的哪个缺失或模糊导致了问题
3. **可落地**：每项加固方案必须给出明确的修改目标文件 + 修改内容描述，可直接执行
4. **就低覆盖**：优先修复高频、高优先级（P0 > P1）、多次重复出现的问题根因
5. **最小改动**：加固方案只补充缺失内容，不重构整个规范文档

---

## 数据来源优先级

| 来源类型                   | 说明                                             |
| -------------------------- | ------------------------------------------------ |
| 评审报告（P0/P1 问题）     | 最高优先级，直接反映 harness 对 Agent 约束的漏洞 |
| CI 报告（残留 Error）      | 反映编码规范未在评审阶段拦截的问题               |
| summary.md 阶段数据        | 反映流程效率（评审轮次、花费时间、打回次数）     |
| Agent 执行过程中的主控观察 | 反映流程卡点、信息缺失、决策歧义等运行时问题     |

---

## 执行流程

> 强制顺序执行，禁止跳步：
>
> **步骤 1（数据采集）→ 步骤 2（根因分析）→ 步骤 3（加固方案设计）→ 步骤 4（输出报告）**

---

### 步骤 1：数据采集

**1.1 定位数据目录**

优先从当前任务的变更目录中采集，路径规律为：

```
.agents/changes/specs/{YYYYMMDD}/{需求名称}/
├── summary.md
├── planning/review/
│   ├── requirements_review_v*.md
│   └── design_review_v*.md
├── coding/review/
│   └── code_review_v*.md
└── ci_result/
    └── ci_report.md
```

若用户指定了具体路径，优先使用用户指定路径。

**1.2 采集内容**

从上述文件中提取以下信息：

| 数据项              | 来源文件        | 提取字段                 |
| ------------------- | --------------- | ------------------------ |
| 各阶段评审轮次      | summary.md      | 阶段总览表「评审轮次」列 |
| 各阶段花费时间      | summary.md      | 阶段总览表「花费时间」列 |
| P0 问题明细         | _\_review_v_.md | 所有标注 [P0] 的问题     |
| P1 问题明细         | _\_review_v_.md | 所有标注 [P1] 的问题     |
| P2 问题明细（选填） | _\_review_v_.md | 所有标注 [P2] 的问题     |
| CI 残留错误         | ci_report.md    | 「残留问题明细」章节     |
| 构建警告            | ci_report.md    | 「打包构建验证」章节     |

**1.3 Agent 执行效率数据**

从主控 Agent 上下文中记录：

- 各阶段是否发生打回（回退次数）
- 流程中出现的歧义点或信息缺失（导致暂停询问用户）
- Agent 产出物缺失或不完整导致的重做

---

### 步骤 2：根因分析

对采集到的每个 P0/P1 问题，按以下框架逐条进行根因溯源：

**根因溯源框架**：

```
问题现象 → 问题类型判定 → harness 根因定位
```

**问题类型判定标准**：

| 问题类型     | 判定条件                           | 典型表现                         |
| ------------ | ---------------------------------- | -------------------------------- |
| 规范缺失     | 相关场景在现有规范文档中无对应说明 | Agent 自行选择方案导致不一致     |
| 规范模糊     | 规范存在但表述不清或有多种解读     | Agent 实现方式错误但可自圆其说   |
| 检查点缺失   | 评审 checklist 中无对应检查项      | 问题通过了评审阶段但在编码中暴露 |
| 模板缺陷     | 文档模板中未包含关键信息采集字段   | 需求/设计文档遗漏关键信息        |
| 流程卡点     | 流程规范未规定歧义场景的处理方式   | Agent 在信息不完整时仍推进       |
| 阶段门禁不足 | 触发条件未覆盖某类异常情况         | P0 问题在错误阶段被发现          |

**根因定位输出格式**：

```
【根因 N】
- 问题来源：{review 报告名称} / {问题 ID}
- 问题现象：{一句话描述}
- 问题类型：{规范缺失 / 规范模糊 / 检查点缺失 / 模板缺陷 / 流程卡点 / 阶段门禁不足}
- harness 根因：{哪个文件的哪个位置缺少什么内容，或表述存在什么歧义}
- 影响范围：{此问题是否会在其他类型需求中重复出现，高/中/低}
```

---

### 步骤 3：加固方案设计

针对每条根因，设计对应的 harness 加固方案。

**加固方案优先级**：

| 优先级         | 触发条件                          |
| -------------- | --------------------------------- |
| P0（必须加固） | 根因来自 P0 问题 / 影响范围「高」 |
| P1（建议加固） | 根因来自 P1 问题 / 影响范围「中」 |
| P2（可选加固） | 根因来自 P2 问题 / 影响范围「低」 |

**加固方案输出格式**：

```
【方案 N】优先级：P0/P1/P2
- 对应根因：【根因 N】
- 目标文件：{.agents/ 下的具体文件路径}
- 修改位置：{章节名称 / 行号范围}
- 修改类型：{新增内容 / 修改表述 / 新增检查项 / 新增门禁条件}
- 修改内容描述：
  {具体要新增或修改的规则/检查项/说明，用文字描述清楚，可直接执行}
- 预期效果：{修改后可防止哪类问题再次出现}
```

---

### 步骤 4：输出报告

按 `references/evolution-report-template.md` 中的模板结构生成自进化分析报告，**直接写入磁盘**。

**默认输出路径**：`.agents/changes/evolution-report-{YYYYMMDD}.md`

**用户指定路径时**：使用用户指定的完整路径，不得修改文件名后缀。

> 报告模板详见：`.agents/skills/self-evolution/references/evolution-report-template.md`

---

## 执行约束

1. **禁止虚构数据**：报告中所有数字和问题描述必须来自真实的评审报告文件，不得估算
2. **禁止重复加固**：加固前先检查目标文件是否已包含类似内容，避免重复添加规则
3. **禁止过度重构**：每个方案只修改最小必要范围，不得借机重构不相关的规范内容
4. **立即执行 P0 级方案**：P0 优先级的加固方案分析完成后应立即执行写入，不等待用户确认
5. **输出路径确认**：若用户未指定路径，在输出报告前明确告知默认路径，允许用户更改
