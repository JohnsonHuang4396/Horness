# 工作规范（Harness 项目骨架，Frozen 层）

本文件是 Harness 项目骨架的**通用工作规范**。以下规则是**不可绕过**的 Frozen 层，任何项目规则都不能覆盖。项目级补充（技术栈坑位、验证命令）请追加到本文件末尾，或由 `/bootstrap` 生成候选。

## 证据纪律

- 每个任务走 `P0→P10` 阶段流水线（命令行 `/harness` 触发），每阶段产出对应的阶段产物文件（模板见 `.harness/templates/`），并把事件写入 `.harness/host-sessions/<session>/adapter-events.jsonl`。
- 证据至少记录：输入路径、内容哈希、输出路径、命令与退出码。无法观察到的进度如实标注「等待当前 AI」，不伪造百分比。
- 任务信息、项目规约、证据 / 系统状态。这些是训练与运行时依据，不是闲聊内容。

## 候选制（禁止把猜测写成正式规则）

- 新规则、Skill、领域知识一律先写成候选，放 `.harness/generated/` 或 `.harness/packs/candidates/`，带来源、置信度、冲突、待确认项。
- 候选必须经过评测、用户审批、灰度安装、回滚验证后才可激活；未审批的候选不能进入生效规则。
- 项目已有同名规则要做差异报告，不直接覆盖已有文件。

## 安全红线

- 不读取、不打印、不提交密码、Token、私钥、完整环境变量和其他秘密。
- 默认不联网；只有用户明确要求访问外部来源时才允许。
- 不删除用户文件、旧数据或冲突源文件；修改必须走备份与回滚路径。
- 发现密钥、P0 安全问题立即阻断并说明处理路径，不静默继续。

## 使用入口

- 完整阶段流水线：`/harness`。
- 项目扫描 / 规则生成候选：`/bootstrap`；重新扫描：`/scan`。
- 验证 Harness 是否真被使用：`/harness-check`；体检：`/doctor`。
- 自进化复盘：`/evolution`；安全卸载：`/uninstall`。
- 实例配置：`.harness/config.json`（项目名称/技术栈/校验/角色等）。
