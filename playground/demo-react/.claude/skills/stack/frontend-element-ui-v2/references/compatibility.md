# Element UI 2.x 兼容性与版本边界

## 版本证据

- 依赖证据优先来自业务项目 `package.json`、锁文件和实际入口。
- `element-ui` 2.x 与 Vue 2 配套；`element-plus` 与 Vue 3 配套，两个库的组件名、事件、插槽和导入方式不能混用。
- Node、Babel、webpack、旧浏览器支持范围必须以项目锁文件和构建配置为准。没有证据时只写待确认，不凭 Skill 默认版本下结论。

## 常见边界

- Vue 2 使用 Options API 和旧的 `v-model` 约定；不要把 Composition API 或 `modelValue` 写法直接迁入。
- 主题变量和组件 CSS 覆盖可能影响整个应用；局部修改前搜索同名变量、全局样式和二次封装。
- 按需引入要同时检查组件注册、样式注册、Babel 插件和生产构建；只看到源码导入不能证明包体真的减少。
- 表格、树和级联组件使用稳定 key；异步数据变化后要重新核对选中值、展开状态和分页。
- Dialog/Drawer 的关闭、焦点、销毁和异步提交要覆盖取消、失败和重复点击。

## 禁止事项

- 不要删除项目已有组件封装来直接替换成官方示例。
- 不要把文档示例中的真实样式、接口、token、Mock 地址复制进生产配置。
- 不要在没有视觉或构建证据时声称升级、主题改造或性能优化完成。
