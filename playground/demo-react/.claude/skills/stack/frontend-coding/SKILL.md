# 编码实施

## 前端编码

## 职责边界

本技能负责**调配技能完成编码**，根据已有文档或需求理解实施编码，集成前端技能调配策略（UI组件库优先级、专项技能调用规则），并在完成后生成编码报告。

## 前置依赖

根据执行模式加载对应文档：

**有设计文档和任务文档（Plan / Spec 模式）**：

- `.agents/changes/{变更目录}/planning/tasks.md`
- `.agents/changes/{变更目录}/planning/design.md`
- `.agents/changes/{变更目录}/planning/requirements.md`
- `rules/工程结构.md`
- `rules/编码规范.md`

**无设计/任务文档（Vibe 模式）**：

- 用户需求描述（直接根据需求理解开发）
- `rules/工程结构.md`
- `rules/编码规范.md`

## 编码实施流程

### 1. 评估任务批次策略

**有任务文档（Plan / Spec 模式）**：

- **任务数 ≤ 12**：一次性执行所有任务
- **任务数 > 12**：建议分两批执行，询问用户偏好

分批拆分原则：

- 按功能模块边界拆分（优先）
- 有强依赖的任务放同一批
- 第一批完成核心功能，第二批完成扩展功能

**无任务文档（Vibe 模式）**：

- 根据需求理解自行规划实现顺序，按分层依赖顺序开发：`config → api(api.js URL常量) → service(service.js 服务函数) → store(Vuex) → router → views`

### 2. 按依赖顺序执行任务

对于每个任务：

**任务开始**：宣布"开始执行任务 X：[任务名称]"

**检查参考代码**：如用户需求中有"参考某功能实现"指示，先查找参考代码文件，按参考代码模式实现。

**检查暂不实现标记**：

- 如需求文档（requirements.md）或设计文档（design.md）中已标注该功能"暂不实现"，则跳过该任务，标记为"已跳过（暂不实现）"
- 如代码中有 `// 暂不实现` 或 `TODO` 注释标记的功能，可保留占位代码或跳过实现

**实现任务**：按任务描述实施编码

**任务完成通知**：简要说明"任务 X 已完成"，列出关键实现点和修改文件，**不暂停**，直接继续下一任务。

### 3. 编码规范（强制）

**查阅优先级（按序执行，有上层覆盖则不查下层）**：

1. **系统解决方案文档**（第一优先级）：涉及系统能力（HTTP请求、埋点等）时，查阅 `.agents/wiki/系统解决方案/` 下对应文档
2. **编码规范文档**（第二优先级）：仅当系统解决方案未覆盖当前场景时，才按需查阅 `.agents/wiki/编码规范/` 目录下对应规范

**核心规范速查（所有代码必须遵守）**：

- 使用 Vue 2 Options API（项目基于 Vue 2.7），导出组件对象包含 `name`、`components`、`data`、`computed`、`methods` 等选项
- 使用 JavaScript（ES6+），所有函数参数必须使用 JSDoc 注释说明类型，变量命名必须语义化
- Element UI 组件通过 `Vue.use()` 全局注册或局部 `import` 导入，无需手动引入已全局注册的组件
- 每个组件必须声明 `name` 选项（如 `name: 'KnowledgeList'`）
- 配置类数据（表单项、表格列定义等）必须抽离到 `config.js` 或同目录 `config/` 下
- 单 Vue 文件不超过 600 行，超出须拆分子组件
- 接口请求依赖全局错误处理（axios 拦截器），禁止额外 try/catch 或判断 `code === '000000'`
- API 前缀在 `api/service.js` 中根据 `window.location.hostname` 动态拼接，URL 常量在 `api/api.js` 中定义，禁止硬编码
- 路由跳转参数使用 `query`，禁止使用 `params`
- 单函数圈复杂度不超过 10，复杂逻辑拆分为子函数
- 分层调用：`views → store(Vuex)/service → api → http(https.js)`，禁止跨层调用；**白名单例外**：API 层中定义的是纯 URL 字符串常量时，views 层可直接引用该 URL 常量
- UI 组件优先级：`Element UI > 自定义组件`

### 4. 生成编码报告

所有任务完成后，**生成报告前必须先执行废弃文件清理**：

**废弃文件清理（强制，生成报告前执行）**：

1. 运行 `git status` 查看所有本次新增（Untracked）的文件
2. 对照变更文件清单，识别"已创建但未纳入清单"的文件（中间草稿、路径变更前的旧版本等）
3. 判定标准：文件由本次任务创建 + 未被路由注册引用 + 未纳入变更文件清单 → 视为草稿，**必须删除**
4. 删除所有草稿文件后，再生成编码报告

使用 `reference/coding-report-template.md` 模板生成编码报告：

- 汇总已完成的所有任务
- 列出所有新增文件清单（文件路径、分层、说明）
- 列出所有修改文件清单（文件路径、变更内容）
- **填写废弃文件声明**：列出编码过程中创建但最终废弃的文件及删除确认；若无则填"无"
- 填写关键实现说明

输出路径：`.agents/changes/{变更目录}/coding/coding_report_v1.md`（版本号递增）

## 技能调配策略

### UI 组件库使用优先级（强制）

**`Element UI > 自定义组件`**

- 优先使用 Element UI 组件（`el-button`、`el-table`、`el-form`、`el-dialog` 等）
- Element UI 无法覆盖时再自定义组件
- 自定义组件按作用域分两层放置：
  - 项目业务组件（跨模块复用）：`src/components/`
  - 页面组件（仅当前页面使用）：`src/views/[module]/components/`

### 技能调配速查表

| 触发场景                                     | 调配技能             | 说明                                        |
| -------------------------------------------- | -------------------- | ------------------------------------------- |
| 使用 Element UI 组件                         | `element-ui-v2`      | Element UI 2.x Vue 2 组件库文档与最佳实践   |
| MasterGo 设计稿还原前端代码                  | `mastergo-mcp-skill` | 获取 DSL → 生成代码 → 验证                  |
| HTTP 请求封装、API 前缀配置、错误处理        | 直接查阅 wiki        | `.agents/wiki/系统解决方案/HTTP请求实例.md` |
| 埋点数据上报                                 | 直接查阅 wiki        | `.agents/wiki/系统解决方案/埋点.md`         |
| 需要查询接口详情 / 接口联调 / 替换 mock 数据 | `api-info`           | 通过接口 ID 获取完整参数、请求/响应结构     |

## 输出产物

## V3 证据和候选边界

- 没有浏览器证据时明确标记未观察。

- 初始化、领域事实、外部 Skill 或项目规范没有得到项目证据和用户确认时，不写入正式规则；否则保持候选。
- 没有真实浏览器、交互式宿主或等价命令证据时，明确标记“未观察”，不能把读取文档或模型推断写成视觉验证通过。
- 入口、references、examples、templates、checklists、evals、脚本和许可证共同构成完整 Bundle；本入口可路由到补充资料，但不能用入口摘要替代完整能力。
