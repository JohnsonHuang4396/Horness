# 需求分析

## 职责边界

本技能负责**需求理解与需求文档生成**的完整执行流程。

## 流程步骤

### 1. 理解用户需求

- 识别需求类型：新增模块 / 迭代开发
- 识别功能性需求和非功能性需求
- 如存在歧义或缺失关键信息（功能边界、数据来源），**必须暂停并向用户提问**

### 2. 接口信息整合

根据是否提供接口 ID，进入对应模式：

#### 模式 1：后端接口已开发（集成真实接口）

**触发条件**：用户已提供接口 ID。

1. 从用户输入中提取接口 ID 列表
2. 为每个接口 ID 调用 `api-info` 技能，获取接口详情（不做文件输出，仅获取内容）
3. 将接口信息整合到需求文档「接口文档」章节

**如未提供接口 ID**：询问用户"是否有相关的后端接口编号？如果有，请提供接口编号（多个接口用逗号分隔）"

- 用户提供 → 执行上述真实接口集成流程
- 用户回复"没有"或"暂无" → 进入模式 2

#### 模式 2：后端接口未开发（Mock 接口定义）

**触发条件**：用户明确表示暂无接口编号。

1. **分析需求功能点**：识别每个功能需要的接口操作（查询、新增、编辑、删除等）
2. **按 Mock 接口模板定义接口规范**，参考 `.agents/skills/api-info/references/api-template.md`：
    - 接口路径：遵循 RESTful 风格或项目约定
    - 请求方式：根据操作类型确定（GET/POST/PUT/DELETE）
    - 请求参数：基于功能需求定义必要参数（TypeScript 格式）
    - 响应数据：定义标准响应结构和字段（TypeScript 格式）
3. **整合到文档**：在「接口文档」章节标注 `【Mock 接口定义】`，完整提供接口规范，同时作为后端开发参考

### 3. 生成需求文档

使用 `reference/requirements-template.md` 模板结构生成 `requirements.md`，按实际需求填充各章节内容。

### 4. 输出产物

- 文件路径：`.agents/changes/specs/{YYYYMMDD}/{需求名称}/planning/requirements.md`
- 向用户展示需求文档全文，等待确认

## 依赖的技能包

- api-info

## 注意事项

- 加载状态已全局统一处理，需求文档中**不需要**列"加载状态展示"为前端交互要求
- 错误处理已全局统一，需求中无需描述 loading 逻辑或 try/catch 处理
- 路由跳转参数必须使用 `query` 传递，如需求涉及页面跳转须在需求文档中明确
- Mock 接口定义须严格遵循 `api-template.md` 格式，请求参数只关注 `restParams`
  部分，使用 TypeScript 类型声明，`?`标注可选字段
