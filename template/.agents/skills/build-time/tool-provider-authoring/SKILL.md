# 工具提供者开发

## 适用时机

- 接入终端、扫描器、浏览器、沙箱、CI、MCP 或外部服务时建立结构化输入输出、风险、权限、幂等、取消、脱敏和证据契约。
- 只在当前项目证据和任务目标同时命中时加载；不因为目录、历史任务或来源项目名称自动触发。

## 进入前检查

- 先读取任务原文、当前项目规则、相关变更文档和已有验证证据。
- 用 Git/文件系统/构建描述做精确取证，区分事实、推断、冲突和未知。
- 检查当前任务的允许写入范围、秘密边界、外部副作用和恢复点。

## 执行流程

1. 先写任务目标、允许范围、当前阶段、Assurance 模式和退出条件；把用户原话、仓库事实、推断和未知项分开。
2. 建立本 Skill 的输入清单和证据索引；每项证据记录路径/命令、时间、哈希或版本，敏感内容只保留键名和脱敏指纹。
3. 依次执行以下专项检查：
   - 定义工具 ID/版本、Schema、平台、能力探测、读写范围、R0-R4 风险、网络、秘密和副作用。
   - 使用结构化 argv/API，限制输出大小、超时、取消、进程清理和不可信内容传播。
   - 为可重试动作设计幂等键和结果探测；不可逆动作提供补偿或人工对账。
   - 所有执行经过 Gateway/Policy，测试拒绝、超时、部分成功、版本变化、恶意输出和秘密脱敏。
4. 复核直接消费者、间接消费者、配置/资源/脚本/测试/部署路径，发现新影响立即暂停并更新影响账本。
5. 只生成当前阶段允许的文件和结构化产物；不把候选事实、设计建议或模型推断写进正式规则。
6. 选择与项目版本匹配的最窄验证，再按风险扩大；记录命令、工作目录、版本、退出码、时长、输出路径和未运行项。
7. 输出中文摘要：已读取、已决定、实际修改/产出、验证证据、未知项、风险、回退和下一步。

## 输出物

- Tool Descriptor 和 Provider
- 证据提取、策略映射和契约测试
- 版本锁、权限和卸载说明

## 质量门禁

- 每个结论都能定位到文件、命令、事件或批准记录。
- 未执行的命令标为未观察，不能写成已通过。
- 报告中的文件、需求、影响和验证项可以逐条核销。
- 失败时保留原始错误和下一条可执行的回退路径。

## 失败与回退

- 输入或目标不清：回到需求确认阶段，列出最少的待确认问题。
- 发现新影响：暂停当前批次，更新影响账本和计划后再继续。
- 工具或环境失败：记录原始输出，区分可重试、需修复和需人工处理。
- 安全、契约或数据一致性失败：阻断交付，不用文字摘要掩盖。

## 明确边界

- 不把模型猜测、目录名或旧摘要当作权威事实。
- 不越过当前阶段职责，不顺手修改无关文件。
- 不读取或输出秘密，不执行未批准的高风险外部动作。

## 最小示例

- 以一个真实的小任务为例，展示输入事实、关键决定、产出文件和验证结果。
- 正向触发：用户任务明确命中本 Skill 的职责，且项目证据可以支撑执行。
- 负向触发：只有相似关键词、没有项目证据、或任务属于另一个阶段时，记录排除原因并不加载本 Skill。
