# Bootstrap（项目扫描与规则生成）

对当前项目做一次**只读**工程扫描，生成规则与 Skill 候选。**不修改业务代码和正式规则。**

## 步骤 1：项目扫描

识别并记录（写入 `.harness/generated/scan-candidate.md`）：
1. 语言、框架、版本、包管理器、源码根目录、测试入口、构建/检查命令、部署和生成目录。
2. 以锁文件、构建描述、入口源码和已有 AGENTS/CLAUDE 内容为准，**不凭目录名猜版本**。
3. 读取 `.harness/config.json` 的 `project.stack`/`project.lang`/`project.packageManager`，按活跃栈检查对应生态；无配置时按探测结果为准。
4. 把事实、推断、冲突、未知项分开记录。

## 步骤 2：规则候选

按已验证扫描事实生成项目规则候选，**不直接覆盖已有文件**。候选至少覆盖工程结构、开发流程、编码规范、生态与版本边界、验证命令、安全红线、生成目录保护、适用范围、证据路径、例外、验证方式、失败回退。已有同名规则时做差异报告而不是覆盖。候选放 `.harness/generated/rule-candidates/`，来源与未决问题写 `.harness/generated/rule-review.md`，等待审核后再应用。

## 步骤 3：Skill 发现

- 检查 `.claude/skills/` 已有 Skill，避免重复安装。
- 优先复用通用 Core/Stack Skill；只有项目证据明确支持时才选专项 Skill。
- 输出匹配项、排除项及证据；没有合适项时明确报告缺口，不要把「查找」变成「设计」。

## 步骤 4：候选产物

- 扫描矩阵：事实/推断/冲突/未知。
- 规则候选：`rule-candidates/`。
- Skill 建议：匹配项 + 证据。

## 安全约定

默认只读本地文件，不联网；不读取/打印/提交秘密；不覆盖用户已有文件；候选不直接激活，等待 Harness 审核。
